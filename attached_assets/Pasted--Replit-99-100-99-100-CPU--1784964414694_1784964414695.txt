レベル99・100の超高難度化

現在のレベル99・100は簡単すぎるため、通常の高難度CPU戦ではなく、固定手札・固定盤面・固定思考による超高難度の詰め大富豪へ変更してください。

INMU大富豪で実装済みのオリジナルルールはすべて有効にします。

共通条件：

* プレイヤー手札は7枚未満にしない
* プレイヤーとCPUの手札は完全固定
* CPU3人
* CPU難易度は最高
* CPUの座席順、開始手番、同点時の行動優先順位も固定
* 再挑戦時も同じ展開を再現
* ランダム要素を使わない
* CPUはプレイヤーの非公開手札を参照しない
* 強いカードを順番に出すだけでは勝てない
* 必ず攻略可能なルートを用意する
* 開発側で全手順を探索し、クリア可能性を確認する

レベル99「三人の罠」

コンセプト

3人のCPUの残り枚数と行動を読み、あえて場を取らない・あえてカードを崩す・あえてパスする判断が必要なステージにしてください。

一見すると革命や8切りを使えば簡単に勝てそうですが、使う順番を間違えるとCPUの誰かが即座に上がる構成にします。

基本条件

* プレイヤー手札：9枚
* CPU A：3枚
* CPU B：5枚
* CPU C：6枚
* CPU3人
* CPU難易度：最高
* 固定手札
* 固定盤面
* CPU Aの手番から開始
* パス可能回数：2回まで
* 制限ターン：24ターン
* クリア条件：1位
* プレイヤーが2位以下になった時点で失敗

プレイヤー手札の構成条件

具体的なカードは既存ルールとの整合性を確認して設定してください。

プレイヤーの9枚には、以下をすべて含めてください。

* 8を最低1枚
* ジョーカー1枚
* 革命を起こせる組み合わせ
* 3枚以上の階段候補
* ペア候補
* 縛りを発生させられる同一スート
* 単体では強いが、先に出すと負け筋になるカード

ただし、すべての役を同時に維持できる手札にはせず、どの役を崩すか判断が必要な構成にしてください。

CPU手札の役割

CPU A：即上がりを狙う相手

* 残り3枚
* 単体、ペア、または階段で一気に上がれる可能性を持つ
* プレイヤーが不用意に場を流すと即座に上がる
* ただし、正しい縛りや場の形を作れば止められる

CPU B：革命対策役

* 残り5枚
* 革命前は弱いが、革命後に強くなるカードを持つ
* プレイヤーが早い段階で革命するとCPU Bが有利になる
* 革命を起こすタイミングを遅らせる必要がある

CPU C：ジョーカー対策役

* 残り6枚
* スペード3またはジョーカーに対抗できる構成を持つ
* プレイヤーがジョーカーを雑に使うと返される
* 終盤までジョーカーを温存する必要がある

必須となる攻略要素

レベル99では、以下の判断をすべて必要にしてください。

* 最初の合法手の中に罠の手を含める
* 1回以上、勝てる場面であえてパスする
* ペアまたは階段を途中で崩す
* 8切りを終盤まで温存する
* 革命を早く起こすと負ける
* ジョーカーを序盤に使うと負ける
* CPU Aの残り枚数を優先して管理する
* 縛りを使ってCPU Aの上がりを止める
* 最後は8切りまたは場流しから連続してカードを処理する

禁止事項

以下のような単純な攻略にはしないでください。

* 最初に革命を起こすだけで勝てる
* 最初に階段を出すだけで勝てる
* 8切り後に強いカードを並べるだけで勝てる
* ジョーカーを最後まで残すだけで勝てる
* CPUがたまたまパスすれば勝てる
* CPUの行動がランダムで攻略が安定しない

難易度目標

* 初見クリア率：1％未満
* ヒントを1つ見た状態：5％以下
* 完全な攻略手順を理解した状態：90％以上
* 最適解ルートは1〜2本程度
* 1手目または2手目の誤りだけで即敗北にはせず、数手後にミスが表面化する構成にする

ヒント表示

敗北回数に応じて段階的にヒントを解放できるようにしてください。

* 5回敗北：「最初から場を取り続ける必要はない」
* 10回敗北：「革命を急ぐと、あるCPUが有利になる」
* 20回敗北：「8切りは最後の処理に必要」
* 30回敗北：「残り3枚のCPUを縛りで止める」

答えそのものは表示しないでください。

レベル100「大富豪・完全詰み崩し」

コンセプト

レベル100は、単純な正解手順一本ではなく、CPU3人の行動分岐を読んで、その都度最適な手を選ぶ最終試験にしてください。

固定手札ではありますが、プレイヤーの出し方によってCPUの合法手や選択が変化し、複数の分岐が発生します。

レベル99が「正しい手順を見つけるパズル」であるのに対し、レベル100は「ルールの総合理解と先読み」を求めるステージにします。

基本条件

* ステージ名：「大富豪・完全詰み崩し」
* プレイヤー手札：12枚
* CPU A：6枚
* CPU B：7枚
* CPU C：8枚
* CPU3人
* CPU難易度：最高
* 固定手札
* 固定座席順
* 通常状態から開始
* プレイヤーの手番から開始
* パス回数制限なし
* ターン制限：35ターン
* クリア条件：1位
* 禁止カードなし
* INMU大富豪のオリジナルルールをすべて有効にする

プレイヤー手札を12枚にすることで、単純にカードが少ない詰め問題ではなく、役をどのように分解・再構成するかを考えさせてください。

プレイヤー手札の構成条件

以下をすべて含めてください。

* ジョーカー1枚
* スペード3
* 8を2枚
* 革命を起こせる4枚組または革命階段
* 4枚以上の階段候補
* 2組以上のペア候補
* 同一スート4枚以上
* 革命前に強いカード
* 革命後に強いカード

重要：

* 最初の状態では複数の役が重複している
* ある役を使うと別の役が作れなくなる
* すべての役を使うことはできない
* 「どの役を捨てるか」が攻略の中心になる
* ジョーカーを階段やペアの代用に使う選択肢もあるが、最終的な正解とは限らない

CPUごとの戦術

CPU A：速攻型

* 残り6枚
* 単体中心
* 8切りを持つ
* プレイヤーが場を弱くすると連続して処理する
* 終盤に残すと最も危険

CPU B：役構築型

* 残り7枚
* ペアと階段を複数作れる
* プレイヤーが役を出すと、同じ枚数のより強い役で返す
* 革命後は手札構成が崩れやすくなる

CPU C：制御型

* 残り8枚
* ジョーカーまたはスペード3を持つ
* 縛りを利用する
* 場を流すカードを温存する
* プレイヤーの残り枚数が少なくなると、場を取らせない行動を優先する

必須となる攻略要素

レベル100では、以下を最低限必要にしてください。

* 3〜5手先まで読む必要がある
* 一度は強いカードを出さずにパスする
* 一度は勝てる役をあえて崩す
* 一度は革命を起こすか起こさないかの分岐判断がある
* 8切り2枚を異なる目的で使う
* 1枚はCPUの速攻阻止
* もう1枚は自分の終盤処理
* ジョーカーを単体以外で使う選択肢がある
* スペード3返しが実際に発生する可能性を作る
* 縛りを自分から発生させる必要がある
* CPUの残り枚数によって優先して止める相手が変わる
* 革命前後で処理するカードを分ける
* 最後の3枚を同じ役で一気に出すだけでは勝てない
* 最後の1枚を出すために、2周以上前から盤面を作る必要がある

分岐構造

最低でも3つの主要分岐を作ってください。

分岐A：序盤に革命した場合

* そのままではCPU AまたはBが有利
* 特定の縛りや8切りを組み合わせれば勝利可能
* 難易度は非常に高い

分岐B：革命を中盤まで温存した場合

* 最も標準的な勝利ルート
* ただし、ジョーカーの使い方を間違えると敗北

分岐C：革命を使わない場合

* 非常に限定的だが勝利可能
* ペア、階段、縛りを正確に管理する必要がある

最低2つ以上の勝利可能ルートを用意してください。ただし、どのルートも簡単にはしないでください。

CPU思考の要件

CPUは以下の公開情報だけで判断してください。

* 自分の手札
* 場に出たカード
* 現在の場の役
* 革命状態
* 縛り状態
* 各参加者の残り枚数
* 既に使用されたカード

CPUは以下を考慮してください。

* プレイヤーが残り1〜2枚なら、可能な限り場を流さない
* プレイヤーが革命を狙っている可能性を公開情報から推測する
* ジョーカーを不必要に早く使わない
* 8切りを終盤の主導権確保に使う
* ペアや階段を崩す価値を判断する
* 他CPUを無条件に助けない
* CPU自身が1位になることを最優先する

禁止事項

* CPUがプレイヤーの手札を見て最適解を選ぶ
* CPU同士が共謀する
* CPUが毎回同じカードしか出さない単純AI
* プレイヤーの初手が実質1択
* 1回のパスだけで勝敗が決まる
* 運やランダム行動待ち
* ジョーカーや2をCPUに大量配布して難しくする
* プレイヤーの手札を弱いカードだけにする
* ターン制限だけで無理やり難しくする

難易度目標

* 初見クリア率：0.1〜0.5％
* 50回以内のクリア率：5％以下
* ヒントをすべて見た状態：20％程度
* 完全攻略を理解した状態：70〜90％
* 最適ルート以外にも、非常に難しい勝利ルートを1つ以上用意する

自動検証

レベル99・100については、通常のランダムシミュレーションだけではなく、全合法手を探索する専用検証を行ってください。

実装内容：

* 各ターンの合法手を列挙
* ゲーム状態を分岐させる
* 同一状態をハッシュ化して重複探索を省く
* 勝利状態まで到達するルートを保存
* 敗北しか存在しない場合は手札を調整
* 勝利ルートが簡単すぎる場合も調整
* 最短勝利手順
* 勝利可能ルート数
* 1手目ごとの勝率
* 重要な分岐点
* ミスをした場合に敗北が確定するターン

これらを開発ログに出力してください。

開発用確認項目

レベル99・100の実装完了後、以下を報告してください。

* プレイヤーの固定手札
* CPU3人の固定手札
* 初期盤面
* 開始手番
* 勝利可能ルート数
* 最短クリアターン
* 想定攻略手順
* 別解の有無
* 各初手からのクリア可否
* 自動探索でクリア可能と判定された証拠
* CPUが非公開手札を参照していないこと

画面上には攻略手順やCPU手札を表示しないでください。開発ログまたは管理者確認用データとしてのみ保持してください。
